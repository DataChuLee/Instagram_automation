# 새 숏폼 종류 추가하기

숏폼 종류(숙소, 쇼핑, …)는 **폴더 하나**로 정의됩니다. 폴더를 넣으면 앱이 다시 켜질 때 자동으로 찾아서, 새 작업 화면에 탭이 생깁니다. 코드를 고치거나 EXE를 다시 빌드할 필요는 없습니다.

## 폴더를 넣는 곳

| 위치 | 용도 |
|---|---|
| `studio/skills/<id>-shortform/` | 앱에 기본으로 들어가는 종류(숙소·쇼핑). 저장소에서 고치고 EXE를 다시 빌드할 때 씁니다. |
| `%LOCALAPPDATA%\StayStudio\domains\<id>-shortform\` (EXE) <br> `.local/domains/<id>-shortform/` (개발 실행) | **새 종류 추가, 기본 종류 덮어쓰기.** 빌드 없이 폴더만 넣고 앱을 다시 켜면 됩니다. |

- 같은 id가 두 곳에 있으면 앱 데이터 폴더 쪽이 우선입니다.
- 앱 데이터 폴더에는 바꾸고 싶은 파일만 넣어도 됩니다. 예를 들어 `shopping-shortform\SKILL_TEXT.md` 하나만 넣으면 쇼핑 대본 규칙만 바뀌고, 나머지 파일은 기본 쇼핑 폴더의 것을 씁니다.
- 덮어쓴 결과가 점검을 통과하지 못하면, 덮어쓰기를 무시하고 기본 종류를 씁니다. 이유는 서버 로그와 `/api/domains/problems`에 남습니다.

## 폴더 구성

```
food-shortform/
  domain.json        # 종류 정의 (필수)
  SKILL_TEXT.md      # 대본 규칙·예시 (필수)
  SKILL_MOTION.md    # 사진 방식: AI 움직임 프롬프트 규칙
  SKILL_ENHANCE.md   # 사진 방식 + enhance 켬: 고화질 변환 프롬프트
  SKILL_ASSESS.md    # 사진 방식 + ai_composition 켬: 후보 사진 평가 지시
  SKILL_SELECT.md    # 사진 방식 + ai_composition 켬: 사진 선택 지시 ({target_count} 자리표시자)
  SKILL_EDIT.md      # 영상 방식: 자막 가림 크롭·구간 고르기 규칙
```

재료 방식별로 꼭 있어야 하는 파일은 이렇습니다.

| media | 필수 파일 |
|---|---|
| `photo` (사진 → AI 움직임 클립) | `SKILL_TEXT.md`, `SKILL_MOTION.md`<br>(+ `enhance`가 켜져 있으면 `SKILL_ENHANCE.md`)<br>(+ `ai_composition`이 켜져 있으면 `SKILL_ASSESS.md`, `SKILL_SELECT.md`) |
| `video` (영상 → 구간 편집, 크레딧은 음성만) | `SKILL_TEXT.md`, `SKILL_EDIT.md` |

## domain.json

```json
{
  "id": "food",
  "label": "맛집",
  "version": "1",
  "order": 15,
  "media": "photo",
  "min_media": 6,
  "max_media": 30,
  "object_types": [
    {"name": "Restaurant", "label": "식당", "description": "영상의 주인공인 식당",
     "properties": [{"name": "name", "label": "식당 이름", "source": "user"}],
     "links": [{"name": "menus", "target": "Menu"}]},
    {"name": "Menu", "label": "메뉴",
     "properties": [{"name": "dish", "label": "메뉴 이름"}],
     "links": [{"name": "restaurant", "target": "Restaurant"}]}
  ],
  "links_from_system": [{"type": "Photo", "name": "shows", "target": "Restaurant | Menu"}],
  "features": {"link_collection": false, "enhance": true, "ai_composition": false},
  "ui": {"upload_title": "맛집 사진을 여기에 넣어 주세요", "caption_default": "여기 줄 서는 이유가 있어요."},
  "disclosure": ""
}
```

| 키 | 필수 | 설명 |
|---|---|---|
| `id` | ✔ | 폴더 이름 `<id>-shortform`과 같아야 합니다. 작업에 저장되므로 한 번 정하면 바꾸지 마세요. |
| `label` | ✔ | 탭과 목록에 보이는 이름 |
| `version` | ✔ | 스키마·프롬프트 버전. 대본마다 "어느 버전으로 만들었는지"가 기록됩니다. 규칙을 크게 바꾸면 올리세요. |
| `object_types` | ✔ | 이 종류의 업무 객체(타입·속성·링크). AI 프롬프트 맨 앞의 `<ontology-schema>`로 들어갑니다. |
| `order` |  | 탭 순서(작을수록 앞). 기본 100 |
| `media` |  | `photo`(기본) 또는 `video` |
| `min_media`, `max_media` |  | 사진(장)·영상(개) 개수 제한. 사진 방식은 `min_media`가 2 이상이어야 합니다. |
| `links_from_system` |  | 엔진 타입 → 내 타입 링크. 예: `Photo.shows → Menu` |
| `features` |  | `link_collection`(여기어때 숙소 링크 전용), `enhance`, `ai_composition` |
| `ui` |  | 화면 문구. 아래 표 참고 |
| `disclosure` |  | 최종 영상 왼쪽 위에 계속 표시할 문구(예: 제휴 고지) |

### 속성의 `source`
- `photo`(기본): AI가 사진·영상에서 읽는 값입니다. 설명용으로만 쓰입니다.
- `user`: 사용자가 화면의 "정보(선택)" 칸에 적는 값입니다. 대본의 사실 근거로 프롬프트에 들어갑니다.

### 엔진 타입 (직접 정의하지 마세요)
엔진이 실제로 저장하는 타입은 앱이 자동으로 스키마에 붙입니다. `object_types`에 같은 이름을 쓰면 점검에서 거부됩니다.

| media | 엔진 타입 |
|---|---|
| photo | `Photo`, `Scene`, `MotionClip` |
| video | `SourceVideo`, `Segment`, `Scene` |

### ui 키
| 키 | 기본값(사진 / 영상) |
|---|---|
| `noun`, `unit` | 사진·장 / 영상·개 |
| `heading` | 사진 & 이야기 / 영상 & 이야기 |
| `select` | 선택한 사진 / 선택한 장면 |
| `analyze` | 사진 분석 & 대본 만들기 ↗ / 영상 분석 & 대본 만들기 ↗ |
| `nav_hint` | ←/→ 키로 사진 이동 / 구간 "보기"로 장면 이동 |
| `facts_title`, `facts_help` | "<label> 정보" / 사용자 입력 칸 안내 |
| `intro`, `upload_title`, `upload_hint`, `caption_default`, `preview_title`, `preview_text`, `ai_help`, `recommend_progress`, `enhance_label`, `photo_name` | 종류별 문구 (`<br>` 줄바꿈 가능: `preview_title`, `preview_text`) |

## 점검 (앱이 켜질 때)
아래 문제가 있으면 그 종류만 목록에서 빠지고 이유가 로그에 남습니다. 나머지 종류는 그대로 쓸 수 있습니다.
- 필수 스킬 파일이 없음
- 링크 대상이 없는 타입임(오타 등)
- 엔진 타입 이름을 다시 정의함
- `min_media` > `max_media`, 사진 방식에서 `min_media` < 2

알 수 없는 `ui` 키나 속성 `source` 값은 경고만 남깁니다.

## 할 수 없는 것 (코드 작업 필요)
- 사진·영상 외의 새 재료 방식이나 새 편집 기능
- 여기어때 외 사이트의 링크 수집
- 객체 데이터 저장. 지금 `object_types`는 AI에게 주는 **설명서**입니다. AI가 찾은 객체(예: 메뉴)를 따로 저장하거나 장면과 연결하지는 않습니다.
- 액션·권한·감사 로그

## 알아둘 점
- 이미 만든 작업은 만든 종류를 기억합니다. 그 종류의 폴더를 지우면 그 작업은 열 수 없고, 이전 작업 목록에는 남습니다.
- 작업 데이터의 `photos`는 "재료 항목" 목록입니다. 영상 방식에서는 영상(`kind: "video"`)이 들어갑니다. 이 이름은 옛 작업과의 호환 때문에 그대로 둡니다.
